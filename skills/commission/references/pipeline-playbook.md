# Pipeline Playbook — flying the five phases (compose, never copy)

How commission runs each phase: which skill it **invokes**, what that invocation gets, what carries forward, and where each phase can stop. commission adds *connective tissue only* — it never reimplements a sub-skill. Each phase's deliverable is a **file**; the file is the contract between phases (and the resume point for a fresh chat).

Two notes that govern the whole run: **answer every question from the exact authorized revision** — the employee's LOCKED decisions are the answers, and what the brief can't answer becomes a wiring ticket or the one batched question, never a mid-run interrogation. And **emit — never fake — any gate that needs a human**: an authorization, a credential, a scope, a real-use signal.

## Phase 0 — Intake (commission's own; no sub-skill)

Runs from a **private case workspace** containing `TOOL_BRIEF.md`. Durable case evidence lands beside it in `build/`; version-control-eligible source belongs in a separate tool repository, normally `tool/`. Local Git eligibility is not publication permission.

1. **Read the whole brief — both halves.** The employee's half above the divider, the builder's half below it. The builder's half is written for you; the employee's half is what you must never contradict.

2. **The entry contract.** Check all three state lines and their revision:
   - `Accuracy: Confirmed accurate <date, exact revision, by whom>` plus `Build authorization: Authorized for build <date, same exact revision, by whom, named build owner>` plus an authorized cost cap → proceed.
   - Selected for evaluation alone, an unconfirmed case, an unauthorized or mismatched revision, or missing authority/cap/build owner → **refuse to start.** Name the exact state gap and offer the appropriate handback. **This refusal is designed behavior and a complete outcome** — a confirmed case need not become a build.
   - Never: build "just the safe parts" without authorization, treat in-brief enthusiasm as authority, or set the state yourself. The single-authority shortcut is valid only when the brief explicitly records one named person controlling data permission, evaluation selection/prioritization, spend, connection/access, construction, and acceptance.

3. **Inventory the brief** into the kickoff's fields:
   - **Decisions in force** — every bullet under Decisions, verbatim. Anything under `### Reversed` stays reversed; never resurrect it. These are not up for relitigation at any phase. **One exception to "verbatim": the stale lock.** A Decision the brief's own later text has already overturned (a correction, a resolved gate, a Shape that contradicts it) is a **stale lock** — flag it for harden's fold-back, quoted, with the brief's own overturning evidence, rather than carrying it verbatim into the kickoff. The employee's own recorded correction is the reversal authority; harden files it under `### Reversed` per the retraction discipline. This retracts a documented reversal the brief failed to file — it never reopens a live decision.
   - **Verification shapes** — the `How to verify:` field, per part. **An older brief may predate this field.** If the builder's half states the shapes unambiguously anyway (e.g. `Model: None` plus monitor-shaped must-be-trues → deterministic + monitor), record that reading in the kickoff and proceed. If genuinely ambiguous, it goes in the batched question — the build may not infer it. **Watch for fossils:** verification artifacts attached to scope the brief itself cut (a sealed set for a generator that's under "Out of scope") are historical, not live — never build to them.
   - **The wiring map** — every Open ask, carried in as-is; withdrawn asks stay withdrawn. Plus, per ask, "what works today without it" — the union of those is the **no-wiring scope**, and it is what's *live* on day one. **Wired scope is still built in the same run** — in full, to the seam, dormant behind its ticket. Wiring defers activation, never construction.
   - **The authorization boundary** — the exact revision, authority holder, named build owner, and Cost line. The run stays inside it; about to exceed it or materially change it → stop and say so.
   - **The case-evidence lifecycle** — copy the brief's exact allowed location, access, retention deadline, deletion method, and owner. Every downstream plan, fixture, log, receipt, and handback remains inside it; construction never silently extends evidence retention.
   - **The fence** — Out of scope, must-be-trues, "What it won't do." The build never grows past these.

4. **The one batched question.** Anything the brief doesn't answer, a file can't establish, and that isn't a wiring ask, gets batched into **one message now** — routed through whoever invoked the run, not fired at the employee piecemeal. If it can't be answered, either proceed on the honestly-narrowed scope (and say so in the handback) or refuse — never guess silently, never interrogate mid-run. Most runs have no question at all: `diagnose` fired the gates up front, and that's the design.

5. **Establish the two-root workspace and commit boundary before any build edit.** Resolve and record two absolute paths: `CASE_WORKSPACE`, containing `TOOL_BRIEF.md` and `build/`; and `TOOL_REPO`, the Git root containing version-control-eligible source, normally `CASE_WORKSPACE/tool`. The case workspace must never be inside the tool repository. For an existing target repository, keep `CASE_WORKSPACE` in a physically separate tree — an allowlist cannot stop a recorder from seeing untracked private files in the same repository. Never rely on ambient working directory or inherited environment: bind both local shell variables from the exact shell-quoted recorded paths before commands, address case artifacts from `CASE_WORKSPACE`, run Git as `git -C "$TOOL_REPO" …`, and run recorder-safe receipt commands from `TOOL_REPO`, for example `(cd "$TOOL_REPO" && didrun run -- …)`.

   Create `build/` and, for a new tool, `tool/`; then classify every input:
   - **Private workspace evidence — never publish or commit:** `TOOL_BRIEF.md`, `private/`, `artifacts/`, `sealed/`, raw or real fixtures, transcripts, build ledgers/logs, and recorder ledgers/refs/objects/exports/reports. These may be necessary to run a local check; necessity does not make them version-control-eligible.
   - **Eligible for local source history:** source under `TOOL_REPO` and synthetic fixtures named by the plan. A deidentified derivative is eligible only with a named authorized data/security owner and date, exact artifact digest, exact repository/history destination, scanner and version/ruleset, covered data types, and explicit passing result. Missing, unsuitable, incomplete, or non-passing evidence means never commit; the builder cannot self-approve. Local source history still does not authorize push or publication.
   - **Secrets never become artifacts:** record the credential's name, owner, scope, and destination — never the value — in briefs, tickets, fixtures, logs, handoffs, or receipts.

   For a new tool, initialize Git at `TOOL_REPO`, never around `CASE_WORKSPACE`. For an existing target repository, preserve its root and write an explicit commit allowlist before editing. Before every commit, stage named allowlisted paths only — never `git add -A` — inspect `git -C "$TOOL_REPO" diff --cached --name-only` and fail closed on any path outside the allowlist, run the required secret scan plus any suitable data/PII scan without printing matched values, and inspect `git -C "$TOOL_REPO" status --short --ignored` so private inputs and generated residue are accounted for. An unavailable suitable scan blocks a deidentified derivative from history; it never becomes a skipped green check. An accidentally committed sensitive file is a hard stop for the named build/technical owner: adding it to an ignore file or deleting it in a later commit does **not** erase history.

   Confirm the receipt tool can produce a real grade from `TOOL_REPO` without crossing the evidence boundary. Inventory its installed version's ledger, Git-note refs/objects, argv/output previews, exports, reports, and other storage. None may be staged, pushed, published, or left outside the brief's deletion plan. Never put credentials, private values, case names, or identifying private paths into recorded arguments, environment, labels, stdout, or stderr. In an existing target repo, private-fixture checks default to direct **UNRECEIPTED** execution; source-only and durable-synthetic checks may be wrapped. A private-fixture receipt requires either a proven non-identifying boundary or an approved disposable clone under `CASE_WORKSPACE`. If any boundary cannot be proven, record the limitation and keep going unwrapped — never fake a receipt.

6. **Emit the kickoff** (`references/kickoff-skeleton.md`), then execute it.

**Where this phase can stop:** missing/mismatched/stale build authorization (refuse + handback offer) · information or authority prevents any safe construction (hand back the tickets and name this as a stopped outcome, not a working tool) · the batched question comes back unanswerable and no honest narrowing exists.

## Phase 1 — `harden` → `build/HARDEN.md` (+ `build/fixtures/`)

- **Invoke `harden`** on the exact authorized revision's **design**. It gets: the full `TOOL_BRIEF.md` (both halves), any permitted example files `diagnose` left behind (exposed examples, exemplars, templates — **never the sealed set**), and the wiring map. It attacks inputs, variants, silent-wrong paths, security, and the thing that breaks in November — and it **never judges worth**; a finding about whether the tool should exist is deleted, not filed.
- **Fold non-material clarifications back into `TOOL_BRIEF.md` under the retraction discipline:** an overturned factual assertion moves to `### Reversed`, restated in past tense with what overturned it — never strikethrough, never deletion. **A reversal isn't done until every sentence asserting the old fact is retracted** — grep the brief for the claim you just stopped believing and fix every hit in the same edit. If harden materially changes employee-visible workflow, intervention, data path, risk, output, cost, or acceptance, create the new revision, set `Accuracy: Draft — needs reconfirmation for <new revision>`, `Evaluation: Not selected for <new revision>`, and `Build authorization: Not authorized`, then stop before sequence.
- **A finding that would reverse a LOCKED decision is not commission's to grant.** Build the safe version inside the lock if one exists; otherwise park the affected scope ("cut by a needed reversal") and route the conversation back in `FIRE_IT_UP.md`. The employee owns the brief's decisions; IT and the build do not redefine the work.
- **A finding that is a gate `diagnose` missed** becomes a four-field wiring ticket (what's needed · who can approve it · roughly how long · what works today without it); the scope behind it enters the wiring/parked ledger and the unwired scope continues.
- **Output:** `build/HARDEN.md` + adversarial input fixtures under `build/fixtures/` — these become make's refusal-suite ammunition and remain private. A separate synthetic derivative may enter local source history; a deidentified derivative additionally requires the complete canonical record above.
- **Where it can stop / be skipped:** a one-prompt tool skips this phase entirely — say so in the narration and the handback.

## Phase 2 — `sequence` → `build/PLAN.md`

- **Invoke `sequence`** (authoring mode) on the revised brief + `build/HARDEN.md`. It maps the briefed scope — Decisions, must-be-trues, Out of scope — onto self-contained, independently verifiable units.
- **Every unit names its verification shape, fixture digests, and case-evidence lifecycle.** The shape and lifecycle come from the brief via the kickoff; the build can't infer them, so the plan carries them explicitly into each unit.
- **Build-then-wire is a sequencing rule:** no-wiring units first. Authorized wired units follow and build safely to the seam — adapter, error paths, honest dormant state, and every check possible without live access. Only activation waits on the ticket; the plan never assumes a gate will clear or promises activation work is always a paste.
- **Degenerate case is legitimate:** one unit, and the plan says so. Don't pad a plan to look thorough.
- **Output:** `build/PLAN.md` — units in order, each with scope, shape, fixtures, and a status row commission keeps current as the run proceeds (this is the resume surface).
- **Where it can stop / be skipped:** never fully skipped — for a one-prompt tool it collapses to the degenerate case (a one-unit `build/PLAN.md` that says so; `make` requires the plan file, and the degenerate plan is cheap and keeps the seam); stops only where missing information or authority makes safe construction impossible, not merely because live access is absent.

## Phase 3 — `make` → source in `TOOL_REPO` + `build/LEDGER.md`

- **Invoke `make` per unit, in plan order.** Each invocation gets: the unit's spec from `build/PLAN.md`, the relevant brief content, the fixtures under `build/fixtures/`, and any exposed examples. **It never gets the sealed set, and never gets this chat's context** — that's what keeps the verification honest.
- **After the last unit, invoke `make` once more for its final whole-tool pass** — the full loop against the brief's complete acceptance (all shapes, the whole refusal suite, cross-unit flows). Units passing in isolation is not the tool passing; this pass is make's own contract, and commission must not skip it.
- **Hold every unit to its brief-named shape:**
  - **deterministic** → replay fixtures: real inputs → the real output the employee actually sent → byte comparison. Visible to the local build, digest-bound, not sealed; the private pair expires with the case. Synthetic derivatives may enter the allowlist; deidentified derivatives additionally need the complete canonical record above.
  - **generative** → verification is an **isolated run whose entire input is the tool + the sealed examples** — never the brief, never the conversation. commission arranges the isolation; make inside the run cannot.
  - **monitor** → replayed state (reconstruct the day it went wrong, run the job, check the output) **plus the silence test** (kill it; confirm the silence is visible to the person, not a log). The liveness stamp ships in v1 or the monitor unit doesn't ship.
- **The refusal suite, every unit:** garbage, empty, wrong-format, truncated, and subtly-wrong inputs produce a visible refusal — break their real file the way their world breaks it; any output at all is a defect. harden's fixtures seed this; make extends them.
- **Receipts:** recorder-safe checks run from `TOOL_REPO`; claim, commit, seal, and gate on strict verify at each unit boundary — it's a loop, not a checkpoint. A private-fixture harness still matches the digest and exercises those same bytes, but remains direct and UNRECEIPTED unless receipt-storage preflight proves the boundary safe. The tree grade binds tool source; the fixture digest in the private case ledger is separate evidence for external input bytes. Grades verbatim; anything unwrapped is called UNRECEIPTED.
- **Commit boundary:** use `git -C "$TOOL_REPO"` to stage only the plan's explicit source/fixture allowlist, inspect cached path names, scan for secrets and the data classes actually present, and inspect status including ignored files before the commit. No autonomous push, publish, live credential insertion, connection, or activation is part of this phase.
- **Non-PASS stops park, never fake.** A unit that can't go green honestly is parked with its stop condition verbatim and its unpark condition named. A provisional pre-seal commit is not landed: on terminal non-PASS, scope-check and locally revert only that unit's commits, record failed/revert SHAs, and continue only with independent units against the restored tree. Never leave failed source landed, rewrite shared history, touch unrelated work, or weaken a fixture.
- **Output:** source in `TOOL_REPO`, plus `build/LEDGER.md` — what was built, how each part was verified (shape by shape), the iteration log, and the honest residual.
- **Where it can stop:** all remaining units parked (run proceeds to snag over what landed, then the handback — partial-but-real beats stalled) · spend cap reached (stop, say so, hand back what's verified so far).

## Phase 4 — `snag` → `build/SNAGS.md`

- **Invoke `snag`** on `TOOL_REPO` against the revised brief: audit → triage → fix, verified local commits. It fixes defects against the brief's must-be-trues and safety defaults — it never adds features, and its triage never weighs worth.
- **Snag findings route like harden findings:** a defect fixable inside the brief → fix it; a finding needing wiring → ticket; a finding needing an employee decision → routed back in the handback, unit parked if load-bearing.
- **Output:** `build/SNAGS.md` — the defect list, what was fixed, what remains, receipts.
- **Where it can stop / be skipped:** optional below a threshold — the tool reads in one sitting AND make's ledger shows every shape verified. Skipping is a judgment call made honestly and **named in `FIRE_IT_UP.md`**, never a silent omission.

## Phase 5 — the handback: `build/FIRE_IT_UP.md` (commission's own, written LAST)

Written after snag, never before — no sub-skill creates or writes this file. When commission writes it, it **folds in every ticket the run flagged** — the four-field tickets recorded in `build/LEDGER.md` (sequence/make units) and `build/SNAGS.md` (the snag pass) — so nothing flagged mid-run is lost; standalone runs of the sub-skills report their flagged tickets in their closing summary instead. Three sections, in this order:

1. **For \<employee\>** (by name): how to start using it today, in plain English written for the person whose job it is. What to open, what to type, what they'll see tomorrow morning. Where their information goes, in words ("to your own Google Drive and nowhere else" — never let "local" stand in for "private"). What it won't do. **Nothing in this section requires a competent technical reader to be safe:** no grades, no receipts, no repo paths, no builder vocabulary.
2. **For the build/technical owner — review and stand it up:** the reduced setup steps; what was verified, in which shape, **in the ledger's words**; where the receipts and fixtures live; the honest residual; what was skipped and why. The named build owner owns undefined construction and code-level review.
3. **For IT/security/access — assigned wiring tickets only:** every applicable ticket in the four-field shape — what's needed · who can approve it · roughly how long · what works today without it — **with evidence attached** and the real activation work spelled out: where the credential or setting goes, the smoke test, and what "working" looks like. IT/security/access may also be the build owner when the brief names it, but never by implication. Plus the **dormant/parked ledger**. Nothing is silently dropped.

The handback also restates the case-evidence deletion deadline, method, and owner. Private fixtures and every recorder surface do not become permanent merely because a build completed; durable regression coverage must come from an eligible synthetic or explicitly approved deidentified derivative.

**Claims discipline:** the handback may claim exactly what `build/LEDGER.md`'s receipts and fixtures verified, in those words — and may never claim "done", "verified", or "working" for anything unverified. **No green checkmark over a stub, ever.** And the firewall line, stated plainly: what's verified is that the recorded checks passed; whether it fits the job is learned only through real use. Confirmation, selection, and authorization are not validation.

## Context / handoff safety-net (whole run)

- **Files are the memory.** Brief → `HARDEN.md` → `PLAN.md` → `LEDGER.md` → `SNAGS.md` → `FIRE_IT_UP.md`. A fresh chat resumes from the files, never from chat memory: re-run intake (the kickoff is a pure function of the brief), then read `PLAN.md`'s status rows and the ledger to find where the run stopped.
- **If context runs low**, emit a `sequence` Mode C handoff (state snapshot + read-these-first + exact next step) so the run continues in a new chat with no amnesia. A long autonomous run is *expected* to span chats; the files make that safe.

## The one rule that keeps this honest

Every phase above is an **invocation of an existing skill**, not a re-implementation. commission's value is the orchestration, the entry contract, build-then-wire, the wiring/parked ledger, and the honest handback — not new capability. If a phase tempts you to inline a sub-skill's procedure, that's the signal to stop and invoke the skill instead.
